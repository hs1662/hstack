# 장애 복구: 상태를 바꾸기 전에

`status`와 `ready`는 관찰 명령이다. 물리적 복구는 `resume --run ID`로 요청한다. 진행률 파일이나 가변 `latest` 포인터로 WAL을 재구성하지 않는다.

| 관측 | 호스트가 할 일 |
|---|---|
| ACK를 받지 못함 | 동일한 요청 본문과 `opId`로 재전송한다. 다른 본문은 `ERR_OP_CONFLICT`다. 이미 영속화된 게이트 측정은 다시 실행하지 않는다. |
| `ERR_GATE_IN_PROGRESS` | 검증 예약은 있지만 완료된 측정이 없을 수 있다. 살아 있는 검증기와 실제 호스트 핸들을 확인한다. 결과를 모르면서 재실행하거나 성공 처리하지 않는다. 필요하면 사유를 남겨 그래프 개정으로 이전 읽기 시도를 펜싱한다. |
| 오래된 토큰, 코드 `49` | 이전 작업자가 반환한 결과를 버린다. 이 토큰으로 핀을 해제하거나 `settle`을 다시 보내지 않는다. 현재 지시서를 `status`로 확인한다. |
| 마지막 프레임에 개행이 없음 | `resume`이 원본 백업을 먼저 남기고 마지막 완전한 경계에서만 절단한다. 백업을 감사 증거로 보존한다. |
| 중간 프레임 손상, 누락된 CAS, `ERR_JOURNAL_CORRUPT` | 해당 Run 사용을 멈춘다. 원본 WAL·스냅샷·핀·CAS를 함께 보존한다. 줄을 삭제하거나 순번을 메워 수동으로 통과시키지 않는다. |
| `ERR_IO_UNCERTAIN` | 저장장치가 쓰기 성공을 보증하지 못한 상태다. 자동 재시도나 표식 삭제로 해제하지 않는다. 오프라인 보존본을 확보하고 저장장치와 마지막 검증된 복구 체인을 조사한다. |
| `ERR_LOCK_RECOVERY_REQUIRED` | 다른 호스트 소유, 소유자 불명 또는 중단된 회수다. `lock/`을 직접 삭제하지 않는다. 동일 호스트에서 사망·PID 재사용이 확인된 경우만 엔진이 고유 무덤으로 이동한다. |
| `retry_wait` / `held_flaky` | 인프라 실패만 기록된 `notBefore`와 예산 안에서 `retry`한다. flaky 진단은 실패 원인 확인용이며 첫 실패와 모든 진단 영수증을 보존한다. 녹색 한 번으로 승격하지 않는다. |

**v2 Run:** 끝나지 않은 게시는 `resume` 때와 다음 `integrate` 때 엔진이 마저 복구한다. `refs/hstack/**.lock`이 남아 있으면 엔진이 작성자 사망을 증명한 경우에만 지운다. 증명이 없으면 `ERR_LOCK_BUSY`다. 이 파일은 손으로 지우지 않는다.

카나리아 인계에는 `latest` 대신 소유자 핀으로 고정한 스냅샷 ID를 사용한다. `gc`는 감사를 위한 과거 WAL이 여전히 참조하는 객체를 지우지 않는다.
